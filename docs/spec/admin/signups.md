# 報名活動管理

`/admin/signups` · `admin` · 權限鍵 `asignup` · `features/admin/SignupManagePage.tsx`

## 用途

看各報名活動的報名情形、確認審核制報名、登錄簽到、匯出名單。**簽到是行政分 ad7/ad8 的唯一資料源**。

## 資料來源

| 動作 | 端點 |
|---|---|
| 活動列表 | `GET /admin/signup-items`(伺服器端分頁,每頁 20,新→舊) |
| 開放中件數 | `GET /admin/signup-items?accepting=true&page_size=1` 的 `meta.total` |
| 報名名單 | `GET /admin/signup-items/{id}/registrations` |
| 修改活動 | `PATCH /admin/signup-items/{id}` |
| 確認報名 | `PUT /admin/signup-items/{id}/registrations/{club_id}/confirm` |
| 場次 CRUD | `GET\|POST\|DELETE /admin/signup-items/{id}/sessions[/{sid}]` |
| 登錄簽到 | `PUT /admin/signup-items/{id}/attendance` |

## 畫面

**列表** — 活動(名稱 + 種類徽章)、截止、已報名(社團數,審核制另標「待確認 N」)、每社上限、狀態(開放中 / 已截止)。右上「+ 建立活動」進 builder。

**管理彈窗**(點列)— 頂部:截止日、已報名社團數與人數、每社上限、「編輯活動」與「匯出名單」鈕。

**編輯活動彈窗** — 活動名稱、地點、活動時間、報名截止、每社名額上限、活動描述、審核制、開放報名。

場次制活動(負責人會議)多一段**場次管理**:場次清單(名稱、日期、刪除)+ 新增場次(名稱 + 日期)。

報名名單逐社一段:社團名、人數、簽到控制、確認狀態或「確認報名」鈕;下方列出每位參加人的姓名、學號、系級與自訂欄位回答。場次制活動的簽到是每場一個勾選框;非場次制是單一勾選框,活動日未到時停用並提示「活動結束後開放登錄簽到」。

## 規則

- **建立後仍可修改**(decisions.md D-09),且**不發通知** —— 打錯字改回來、把地點寫清楚,每改一次推一則只會淹掉頻道
- **報名截止只能改到現在或未來**:往回改等於用系統時鐘偽造「當時就截止了」。要提前收單請取消「開放報名」
- **活動種類不可改**:它同時決定行政分採計(ad7/ad8)與是否場次制,改掉會讓既有場次與簽到失去意義
- **表單欄位一有社團報名就鎖住**(`SIGNUP_FIELDS_LOCKED`):既有回答以現行 key 存,改名或刪欄會讓那些答案在名單與匯出裡憑空消失。UI 目前不提供欄位編輯,端點保留給零報名時的修正
- 表單欄位固定前置三個基本欄位 `name`/`studentId`/`dept`(建立時由前端加上),自訂欄位由後端補 `f1`、`f2`… 的 key
- 審核制活動未確認的報名**不可登錄簽到**(後端 409)
- 確認前先鎖住該張報名單:重複點擊的第二次會讀到已確認而回 409,不會再推一則通知
- 未報名的社團不可登錄簽到 —— 評鑑僅採計簽到,報名是前提
- 場次日期未到不受理簽到(後端 409)
- 非場次制活動的簽到自動建立/沿用單一預設場次,讓簽到只有一個資料源;建立前先取該活動的 advisory lock(`signup_item`),並發登錄不會各建一列
- 刪除場次會連帶刪除該場出席紀錄(FK CASCADE)
- CSV 匯出逐人一列:社團、姓名、學號、系級、各自訂欄位、報名狀態
