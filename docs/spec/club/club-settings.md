# 管理項目

`/club-settings` · `club` · `features/club-settings/ClubSettingsPage.tsx`

## 用途

社團自己維護的資料:指導老師、社團簡介、聯絡與通知、對外公開資料、社團形象圖、更換密碼。頂欄帳號選單的「設定」也指到這裡。

**對外公開資料**這張全寬卡(形象圖收在卡內)填的東西會出現在免登入的社團導覽頁(見 [../shared/club-directory.md](../shared/club-directory.md)、[../shared/club-detail.md](../shared/club-detail.md)),其餘各卡一律不對外。

## 資料來源

| 動作 | 端點 |
|---|---|
| 讀取 | `GET /club/profile` |
| 儲存 | `PATCH /club/profile` |
| 上傳頭像 | `POST /club/profile/avatar` |
| 上傳橫幅 | `POST /club/profile/banner` |
| 移除圖片 | `DELETE /club/profile/avatar`、`DELETE /club/profile/banner` |
| 改密 | `POST /auth/change-password` |

## 畫面

單一表單,右下角統一「儲存」。被改過的欄位加橘黃外框(`.field-dirty`),有變更時「儲存」左側顯示「尚未儲存」。

由上而下三段:

| 段 | 版面 | 卡片與欄位 |
|---|---|---|
| 1 | 2 欄 | **指導老師** — 校內(姓名必填、系所 / 職稱、Email)、校外(姓名、單位/職稱、Email,全選填);**不記錄電話**(D-22,欄位連同舊系統遷入的號碼一併移除)<br>**社團簡介** — 社團名稱(唯讀)、英文名稱(唯讀)、社團網頁連結(必填)、簡介(必填)|
| 2 | **全寬** | **公開資料** — 分四段:形象圖(頭像 1:1、橫幅 3:1)/ 社團資訊(一句話介紹、招生狀態、標籤、社辦位置)/ 對外聯絡(對外聯絡信箱、Instagram、報名連結)/ 給想加入的人看的(例行活動時間、入社方式與社費)。右上角一顆「預覽社團頁」|
| 3 | 2 欄 | **聯絡與通知** — 聯絡通知信箱 1(必填)、2、3、Discord Webhook URL<br>**更換密碼** — 目前密碼、新密碼、確認新密碼 |

第 2 段是唯一會出現在校外的內容,因此**獨立成一個全寬區塊**擺在對內設定之上 —— 與旁邊並排會讓人分不出哪些欄位有人看得到。

## 規則

- 密碼三欄只要填了任一欄就三欄一起驗;密碼與 profile 是兩支 API,profile 成功而改密失敗時只有密碼欄維持 dirty
- **網頁連結與簡介必填**(2026-08-27 需求方拍板)。前端只在**這次真的要存 profile** 時擋(`fields.profileChanged`,與送不送 PATCH 同一個判定)—— 密碼是同一張表單裡的另一支 API,而遷入的社團有一批簡介是空字串、網頁連結是 NULL,一律擋等於那些社團連改密碼都送不出去。後端 `ClubProfileUpdate` 則是只要帶了這兩欄就必須非空,直呼 API 也清不掉
- 網頁連結填了即得 ad6 的 5 分(不追蹤更新時間)
- Discord Webhook 前端驗 `https://discord.com/api/webhooks/…`;該社事件只推這裡,**未填即整社不推**(學務處不收副本)
- 聯絡信箱是公告 Email 通知的收件人
- 社團名稱、英文名稱與屬性(自治性/學藝性…)不可自行修改,只能由行政端改;英文名稱不在 `ClubProfileUpdate` 裡,社團端直呼 API 帶這一欄也寫不進去
- profile 變更寫 `audit_logs`
- 停權中時頁首顯示停權 pill 與到期日,停權原因收在 Tooltip(共用 `components/ui/SuspensionNote`,借用四頁同一則;到期日已過的殘留值不顯示)。**社團資料查詢失敗且手上沒有資料時改顯示「無法確認停權狀態」** —— 什麼都不說等於宣告「沒有停權」;背景重抓失敗則沿用已知的停權事實
- 校內指導老師姓名的必填與兩個 Email 的格式由 schema 收口,直呼 API 也清不掉、塞不進壞格式

**形象圖**

- 圖片**不隨表單儲存**:選檔即上傳(自己的端點、自己的 loading),因此「尚未儲存」與 dirty 外框不涵蓋這兩張圖。理由是圖片要在上傳後才有預覽可看,壓進 PATCH 就得先傳一次暫存檔再綁定
- 收 10MB 以內的常見影像格式(同 `IMAGE` 政策,含 HEIC/HEIF/AVIF;上限讀 `GET /club/config`,前端不放容量常數),**後端一律轉成 WebP 並縮到目標尺寸後才落盤**:頭像 512×512、橫幅 1800×600。原圖不保留,要換尺寸就請社團重傳
- **不做互動裁切**:比例不合的圖由後端 `ImageOps.fit` 置中裁切。要精準構圖的社團自己先裁好再傳 —— 一套 cropper UI 換不到等值的效果
- **橫幅上不壓任何文字**,所以沒有黑化、模糊與字色這些參數(mock 驗證時一併移除)。橫幅是 3:1,字卡與社團頁**用同一個比例**,兩邊都不裁切
- 兩個預覽框**等高**(132px),寬度由各自的比例推出來,並排時上下緣才對得齊
- 形象圖不計入社團儲存配額(`files.club_id` 為 NULL):社團不該為了傳結案照片刪掉自己的橫幅
- 選檔的 `<input type="file">` 要用 `display: none` 藏,不能用 `hidden` 屬性 —— 後者會被 AntD 的 `input` 規則蓋掉,原生的「選擇檔案」鈕就整顆露出來,畫面上變成兩顆按鈕

**預覽社團頁**

- 開新分頁到 `/clubs/:id`,看到的是**已儲存**的內容;表單有未儲存的公開欄位變更時先跳確認(密碼欄不算 —— 它與公開頁無關)
- 被行政端下架(`public_visible=false`)時這顆鈕**反灰**,Tooltip 說明原因。`public_visible` 唯讀下發給社團:開關仍只在行政端,但社團要知道自己公不公開,否則按下去只會撞 404,看起來像系統壞了

**公開資料**

- 這一段的每一欄都可以空白。空白就是那一段不出現在公開頁,不是顯示空欄位
- 標籤是**固定主檔**(14 個,`schemas/clubs.CLUB_TAGS`),至多選 3 個,選滿即停用其餘。自由填寫會讓導覽頁的篩選長歪:同一件事會出現「程式」「寫程式」「Coding」三種寫法,篩選器列不完也對不起來
- 主檔以後改動時,庫裡的舊標籤由後端**丟掉而不是回 422** —— 前端每次 PATCH 都原樣送回整個 `tags`,而挑選器只畫得出主檔裡的按鈕,擋下來的話那個社團連改一句一句話介紹都送不出去,而畫面上看不到也刪不掉那個標籤
- Instagram **只存帳號 ID**:貼整串網址(含 IG 分享連結的 `?igsh=…`)、省略 scheme、帶 `@` 都收得下來,由 schema 正規化
- 對外聯絡信箱與下方「聯絡與通知」的三組信箱是**兩回事**:那三組是公告通知的收件人,屬內部設定
