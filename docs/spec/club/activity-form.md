# 活動申請

`/activities/new`、`/activities/:id/edit` · `club` · `features/activities/ActivityFormPage.tsx`

## 用途

新增活動申請,或編輯草稿 / 被退回的申請。同一個元件兩用。

## 資料來源

| 動作 | 端點 |
|---|---|
| 經費科目與上傳上限 | `GET /club/config` |
| 編輯時載入 | `GET /club/activities/{id}` |
| 建立 / 更新 | `POST /club/activities`、`PUT /club/activities/{id}` |
| 上傳 / 移除附件 | `POST\|DELETE /club/activities/{id}/attachments[/{fileId}]` |
| 送審 | `POST /club/activities/{id}/submit` |

## 畫面

兩欄。

**左:基本資料** — 活動名稱、活動類型(社課或會議 / 活動)、地點、開始日期、開始時間、結束日期、結束時間、社員參加人數、非社員參加人數、活動內容(≤150 字,唯一非必填)、工作分配(項目 + 負責人,自動增列)。

類型選「活動」時右側出現「大活動」勾選框 + 說明 Popover(50 人以上 / 連辦 2–3 天 / 逾 20 小時 / 經費 10 萬以上 / 籌備 3 個月且 5 次會議)。

**右:經費明細 + 附件** — 每列為科目下拉 + 自籌 + 擬請 + 說明,選到有 hint 的科目時下方顯示提示;底部顯示自籌合計與擬請合計。附件只收 PDF(魔術位元組驗證),加總上限由 `system_settings.activity_attachment_total_mb`(預設 15MB)決定;「已使用 X/Y MB」的 X 含單據上既有的附件,Y 是總上限。

底部兩顆鈕:暫存草稿、送出申請。

## 規則

- 進頁前必須先載入 `/club/config`(預設經費科目來自後端),未載完顯示 Spin
- 編輯模式只接受 `draft` 與 `rejected`,其他狀態直接導回 `/activities`
- 選了開始日期而結束日期為空時,自動帶同一天
- **日期選擇器禁選今天以前**;送出時另檢查「開始時刻不得早於現在」,前後端各一道
- 暫存草稿:允許部分填寫(至少填一欄),但 `rejected` 件的「儲存修改」走完整驗證 —— 退回件不能退化成部分填寫的草稿
- **草稿不保存新選附件**,有選檔時彈確認說明將捨棄
- 送出流程是三步:先存(POST/PUT)→ 逐檔上傳附件 → `submit`。任一步失敗都會停在「已存為草稿」狀態並導向編輯頁,不會重複建立
- `is_large` 一改動,後端把 `is_large_approved` 清為 NULL(舊認可不沿用)
- 送出後後端補驗必填八項(名稱、起訖日、起訖時間、地點、工作分配、參加人數合計 > 0)與未來時刻

## 未完成 / 問題

- 活動已過期的退回件無法重送:日期選擇器與後端都禁過去時刻,社團只能竄改成未來日期或放棄
- 承辦人核定金額不受「擬請補助」上限約束(見 [admin/review.md](../admin/review.md))
