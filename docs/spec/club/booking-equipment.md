# 器材借用

`/bookings/equipment` · `club` · `features/bookings/EquipmentPage.tsx`

## 用途

借器材。借用區間由社團自填(含活動前籌備與活動後驗收)。

## 資料來源

| 動作 | 端點 |
|---|---|
| 器材主檔 + 可借數 | `GET /club/equipment?start=&end=`(不帶區間只回粗略值,畫面不採用) |
| 關聯活動下拉 | `GET /club/activities?status=approved&ended=false`(已結束由後端篩掉);查詢失敗時下拉說「活動清單載入失敗」,不說「無審核通過之活動」 |
| 正在借用 / 最近借用 | `GET /club/equipment-loans?active=true\|false` |
| 送出 | `POST /club/equipment-loans` |
| 取消 | `POST /club/equipment-loans/{id}/cancel` |

## 畫面

左右兩欄。

**器材一覽**(左)— 品項、點交方式(一般 / 依序點交)、可借 / 總數。未填借用區間前可借數顯示 `—` 且整列不可點;可借 0 的列灰底不可點。點列即把品項帶入右側表單。

**借用申請**(右)— 關聯活動、借用區間、品項、數量、用途、聯絡電話。借用總覽的器材格點入時(`?equipment=&date=`)帶入品項,起訖日同為該日。

下方兩張表:正在借用(品項、期間、活動/用途、收件人、狀態、取消)、最近借用(多一欄收件/歸還人;伺服器分頁,每頁 5 筆;退回件與承辦撤銷的取消件整列可點,開出原因與時間,舊資料沒留原因時彈窗說明)。

## 規則

- **借用區間由社團自填**:有些活動要提前籌備、事後驗收,從活動起訖推導一律不準。開始日不得早於今天(前後端皆驗),結束日不得早於開始日,**區間最長 60 天**(`booking_service.MAX_LOAN_DAYS`,經 `GET /club/config` 下發給前端即時檢核)—— 沒有上界的話一張還沒審的單就能把某品項的可借數壓到天荒地老(pending 亦佔用)
- 可借數 = 總數 − 該區間內重疊的未歸還未退回借用量(pending/approved/checked_out 都算佔用)
- 數量上限 = min(區間可借數, 該器材 `max_lease_count`);兩者都是後端權威
- 換區間即重推可借數,原選品項在新區間不可借時自動清除
- 一單一品項;多品項要開多單,點交與逾期各自獨立
- 送出時以 `pg_advisory_xact_lock` 鎖器材,序列化「檢核 → 寫入」
- 已結束的活動不能借
- 停權中的社團頁首顯示停權標示與到期日,送出鈕停用(後端亦擋);社團資料查詢首載失敗時改顯示「無法確認停權狀態」
- 退回與撤銷原因來自 `approval_records` 最後一筆 REJECT/REVOKE,隨清單端點一併回傳;退回件一律可點(沒留原因時彈窗直說),「已取消」只有承辦撤銷的那種可點
- **聯絡電話只收 09 開頭的 10 碼手機或 4 碼校內分機**,規則與臨時場地借用同一份(`lib/form.normalizePhone` / `PHONE_RULE`;後端 `_validate_phone_required`)
- 申請時填的聯絡電話會回給工讀生端(`schemas/staff.py`,三頁的 API 都帶):現場點交與催還都要當場聯絡得到人 —— 但目前只有借出點交與逾期追蹤畫面真的顯示,歸還點交頁沒有渲染
