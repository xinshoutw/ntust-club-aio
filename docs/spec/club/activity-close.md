# 活動結案

`/activities/close`(可帶 `?id=`) · `club` · `features/activities/ActivityClosePage.tsx`

## 用途

已核准且已結束的活動填成果調查、學習心得與照片,送承辦人單關審核。結案通過才計入競賽行政分。

## 資料來源

| 動作 | 端點 |
|---|---|
| 可結案清單 | `GET /club/activities?status=approved`(取 `can_close=true`) |
| 詳情與草稿 | `GET /club/activities/{id}` |
| 上傳上限 | `GET /club/config` |
| 存草稿 | `PUT /club/activities/{id}/close-draft` |
| 上傳 / 移除照片 | `POST\|DELETE /club/activities/{id}/photos[/{fileId}]` |
| 上傳 / 移除結案附件 | `POST\|DELETE /club/activities/{id}/docs[/{fileId}]` |
| 送出結案 | `POST /club/activities/{id}/close` |

## 畫面

未選活動時:可結案活動的卡片清單(名稱、日期時間地點、有草稿時標「結案草稿」)。頁首另有下拉可選;清單查詢失敗時卡片區與下拉都說「載入失敗」,不說「目前沒有可結案的活動」。

選定後四區:

1. **活動成果調查** — 實際社員人數、實際非社員人數、實際開始時間、實際結束時間、實際地點、活動重點(類型為社課或會議時顯示為**課程重點**)、如何達成活動目標、其他執行狀況與成果。人數/時間/地點的 placeholder 是申請時填的預估值。
2. **檢討會議** — 是/否;選「是」時檢討會日期、與會人數(≥1)、討論事項、內容決議全部必填。
3. **學習心得** — 每列姓名 + 系級 + 內容,自動增列,最少保留 3 列。
4. **附件與經費** — 活動照片(縮圖牆 + 「選擇照片」「選擇附件」兩顆鈕)、結案附件清單、影片連結、實際支出。**已用 / 上限**印在區塊標題列右側:照片與結案附件**共用同一個額度**(`close_photo_total_mb`),兩處各印一次會讓人以為有兩個。

底部:取消、儲存草稿、送出結案。

## 規則

- 只有「影片連結」非必填,其餘全部必填
- 照片與結案附件**都在按下送出時才上傳**,不隨草稿保存;送出失敗會一起回滾本次已上傳的檔案,避免留下孤兒檔擋住重傳
- **結案附件**收 PDF / DOC / DOCX / 影像(正好是站內預覽支援的四類;舊系統不限格式,搬過來就是一堆開不起來的 zip)。用途是保單、租車資料(行照/駕照/租賃契約)、講師資料、會議紀錄、簽到表這類文件 —— 成果報告表與學習心得由系統依模板生成,不在此列。**選填**,照片仍是必填(至少 1 張)
- 頁內照片去重用 SHA-256;跨活動重複由後端 `uq_files_club_report_photo_sha` 拒絕
- 畫面上的既有照片有兩種來源:**結案送出後被退回**(`close-reject` 不刪照片,是常態路徑)或送出失敗而回滾沒刪乾淨。畫面**不分辨也不加說明** —— 對社團來說都是「已經在伺服器上、佔加總與張數、按 × 就刪掉」,分辨了也不影響他要做的決定;與新選的照片長得一模一樣
- 實際結束時間須晚於開始時間 —— **僅單日活動比較**;跨日活動(18:00 → 翌日 10:00)整段合法,前後端同規則
- 自籌與擬請皆為 0 時,實際支出自動預填 0
- 後端另擋:活動未結束不可結案、逾期鎖定不可結案、零照片不可結案;結案退回後重送會整份取代舊的 `activity_reports`
- **結案被退回即解除鎖定**(decisions.md D-05):結案已在期限內送到,補件的往返不該再被期限擋下 —— `close-reject` 把 `close_unlocked` 設為 true,社團自己重送得了,不必請行政解鎖。該活動仍列在行政端「逾期未結案」中,只是不再屬於「鎖定」那一類
- 送出後狀態轉 `closing_pending_advisor`,草稿清空,推 Discord
