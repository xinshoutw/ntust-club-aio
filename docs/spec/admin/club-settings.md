# 管理項目(行政端)

`/admin/club-settings` · `admin` · 權限鍵 `aclubset` · `features/admin/AdminClubSettingsPage.tsx`

## 用途

社團主檔與帳號管理:改名稱、改類型、改性質、改帳號、啟停用、重設密碼、**公開顯示開關**。社團自己維護的內容(含對外公開資料)在此**唯讀**。

## 資料來源

| 動作 | 端點 |
|---|---|
| 新增社團 | `POST /admin/clubs`(入口在帳號管理的社團分頁,權限鍵仍是本頁的 `aclubset`) |
| 詳情 | `GET /admin/clubs/{id}` |
| 更新 | `PATCH /admin/clubs/{id}` |
| 重設密碼 | `POST /admin/clubs/{id}/reset-password` |
| 建立帳號 | `POST /admin/clubs/{id}/account`(入口在帳號管理) |

## 畫面

左右兩張卡。

**社團資料**(唯讀)— 校內指導老師、校外指導老師、網頁連結、簡介、聯絡 Email、Discord Webhook(只顯示「已設定/未設定」,**不回傳實值**)、**對外公開資料**(頭像與橫幅縮圖、一句話介紹、標籤、招生狀態、對外聯絡信箱、社群連結、社辦位置、例行活動時間、入社方式、報名連結、成立年份)。公開資料全空時該段顯示「尚未填寫」,不鋪一排 `—`。詳情載入失敗且手上沒有資料時,兩張卡都改顯示失敗原因與重試 —— 整排 `—` 看起來像「這社什麼都沒填」;背景重抓失敗則資料照舊、底下補一行說明。

**帳號與狀態**(可編輯)— 社團名稱、**英文名稱**(社團端唯讀,只有這裡改得動)、類型(社團/學會)、性質、社團帳號、帳號狀態開關、**公開顯示開關**、停權中提示;底部「重設密碼」與「儲存」。

修改過的欄位加橘黃外框。切換社團時若有未儲存變更會先確認,取消則留在原社團。

## 規則

- 名稱結尾是「社」或「會」時**自動推導類型且類型下拉停用**;其他結尾才手動指定。前後端各一份 `deriveKind` / `derive_kind`
- **性質改得動**:`POST /admin/clubs` 建檔時性質是必填,而性質是選單與漏斗的資料夾分類,沒填的社團會落在「未分類」—— 選錯了若只能動 DB,等於建完就修不回來。既有的空值(停社遷入舊社,性質不可考)不強迫補,下拉以「未分類」為 placeholder;選了之後不給再清成空白
- 只送有變更的欄位;顯式 `null` 視同未提供(名稱、類型、性質、帳號皆不可清空)。**英文名稱是唯一清得掉的一欄**:送空白即存 NULL(不留空字串,同一欄不要有兩種「沒填」)
- **公開顯示開關(`public_visible`)是行政端的下架閥**:關掉即該社從所有公開端點消失(導覽頁、詳細頁一律 404),社團端照常填寫與上傳。公開頁的圖與文字是社團自己傳的,出事時要能不進 DB 就關掉;預設開啟,關閉時須填原因寫入 `audit_logs`
- 公開顯示與帳號狀態是**兩個判定**:停用社團本來就不出現在公開頁(`is_active` 先擋),但公開顯示關掉的社團帳號仍能登入做事 —— 一個開關兼差兩用不是多擋就是少擋
- 停用社團時**主檔與帳號同步停用並立即撤銷所有 session**;儲存前跳確認
- 重設密碼:產生一次性密碼、寫 `password_history`、`must_change_password=true`、清除鎖定計數、撤銷所有 session。明碼只在該次回應出現,以彈窗一次性顯示
- 所有變更寫 `audit_logs`
- **性質「清單」維持寫死**(decisions.md D-10):自治性/學藝性…這組選項不會變動,是公告分眾與統計的依據,只需上線前核對一次

## 未完成 / 問題

- **個別社團的性質改不了**:`AdminClubUpdate` 沒有 `attribute` 欄位,本頁與 API 都不能調整某一社的性質,只能動 DB(D-10 鎖的是選項清單,不是這件事)
- 停權與解除停權在逾期追蹤頁(權限鍵 `aoverdue`),本頁只顯示停權狀態不能操作
