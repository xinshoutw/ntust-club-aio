# 已知問題

「已經做了但做錯或不合理」的清單。還沒做的見 [gaps.md](gaps.md),逐頁細節見 [spec/](spec/)。

嚴重度:**阻擋** = 上線前必修 · **高** = 會讓人做錯事或丟資料 · **中** = 體驗或維運問題。

## 2. 畫面說一套、系統做一套

| 編號 | 嚴重度 | 問題 |
|---|---|---|
| ISS-07 | 中 | **借用總覽的圖例少了「不開放」**。灰白格沒有任何說明 |
| ISS-08 | 中 | **只允許固定借用的場地在場況圖整列顯示「不開放」**(`cellOf` 以 `allow_temp` 判定)。社團看不出這個場地其實可以固定借用 |
| ISS-09 | 中 | **報修與郵局異動的附件前端必填、後端允許零附件**。兩者都是「先 POST 主體、再上傳附件」的兩段式流程,附件那步失敗時單子已經建立,而列表沒有任何逐列補傳入口 —— 社團只能再送一張新單,系統累積無佐證的重複單 |

| ISS-12b | 中 | 活動申請的**工作分配與參加人數是純前端必填**:後端 `_require_complete` 只檢核名稱、起訖日期、起訖時間、地點,`staff_text` 與人數完全不驗 |
| ISS-12c | 中 | 評鑑上傳鎖(`eval_settings.unlocked`)**看不到也設不了**:`AwardDetailOut` 不回任何鎖定旗標,上傳鈕永遠可按,社團選完檔才吃 409;而 `EvalSetting` 全後端只有讀、沒有任何寫入端點或 UI |

## 4. 會遺失資料

| 編號 | 嚴重度 | 問題 |
|---|---|---|
| ISS-19 | 高 | 成員列表**行內編輯 blur 即送出 PATCH**,沒有確認也沒有復原。後端已略過未變更欄位,所以誤觸未改值不會動 `updated_at`;但只要真的改了值,`onupdate=func.now()` 就會蓋掉 `updated_at` —— 而遷移是把舊系統的**入社日期**寫進 `created_at` 與 `updated_at`,`MemberOut` 又只吐 `updated_at` 並在畫面顯示為「更新時間」。也就是說:一次行內編輯就永久蓋掉那份入社日期的可見副本(`created_at` 裡的那份還在,但 API 從不回傳) |
| ISS-20 | 高 | **評審評分沒有截止或凍結機制**。成績公布後仍可覆寫,`review_scores` 只有一列、舊分數不留痕 |

## 5. 權限與資料邊界

| 編號 | 嚴重度 | 問題 |
|---|---|---|
| ISS-23 | 阻擋 | **檔案下載對 admin 一律放行**:`can_access` 對 `UserRole.ADMIN` 直接 `return True`。只持「檔案管理」權限的管理員可下載全系統檔案,包含郵局存簿影本這類個資 |
| ISS-24 | 高 | **權限鍵前後端命名未統一**(`areview`/`aact`、`asignup`/`areg`),靠 any-of 硬撐 —— 報名管理走 `require_permission("areg","asignup")`,活動審核則是 `admin_activities._reviewer` 自訂的 any-of。後端白名單兩套都收,DB 裡兩套鍵皆合法。**必須在正式建帳號之前統一**,否則之後改要動所有既有帳號的 `permissions` |
| ISS-25 | 中 | 社團帳號重設密碼在兩個頁面的**頁面門檻**不一致(帳號管理頁需 super、管理項目頁只需 `amember`),但兩處打的是同一支 `/admin/clubs/{id}/reset-password`(`AccountsPage.tsx:221` 與 `AdminClubSettingsPage.tsx:165` 同用 `useAdminClubMutations`)。`_MANAGED_ROLES` 不含 `CLUB`,super 那支 `/admin/accounts/{id}/reset-password` 重設不了社團帳號 —— 待決的是這個動作該歸 super 還是 `amember` |
| ISS-26 | 中 | 資料庫層沒有「一社一帳號」唯一約束,只靠應用層檢查,而遷移腳本又繞過應用層 |

## 7. 併發與競態

| 編號 | 嚴重度 | 問題 |
|---|---|---|
| ISS-37 | 低 | 行政分審核彈窗的 `clubId` 綁在 context 上而非開窗當下的快照,理論上「換社團 → 送出」會落錯庫。**實測不可觸發**:AntD Modal 的遮罩擋掉滑鼠、focus trap 擋掉鍵盤,彈窗開著期間到不了下方表格,自動刷新路徑也被 `staleTime`/`refetchOnWindowFocus:false` 排除。屬缺防禦而非缺陷,修法是開窗時快照 clubId 或 `key={clubId}` |
| ISS-39 | 中 | 固定借用「每社 10 節」上限的檢查沒有鎖,並發送出可拿到 20 節。注意**照抄核准端的鎖法修不好** —— 那裡鎖的是 `venue_id`,而 10 節是**每社**額度,鍵應該是 `club_id`(或社團 × 學期) |
| ISS-40 | 中 | **固定借用完全不檢核場地不開放規則**(申請與核准都不檢核)。社團可以借到整學期被標「不開放」的時段,核准後場況圖也不顯示自己的格子(`blocked` 蓋過一切)。而且 `FixedRoomPage` 根本不查場況 API,社團選格時對不開放規則與既有已核准固定借用是**全盲**的 |
| ISS-41 | 中 | 行政分調整的「註銷舊值後新增」沒有鎖,並發可留下兩筆同時生效的調整 |
| ISS-42 | 中 | 密碼重設與登入可競態,產生「重設後舊密碼仍有效」的 session |
| ISS-43 | 中 | 系統磁碟容量檢查存在 TOCTOU,並發大檔上傳可一起耗盡主機磁碟 |
| ISS-44 | 中 | 非場次制報名的預設場次是 get-or-create,並發登錄可能建立重複列 |
