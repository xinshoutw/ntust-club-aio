# 活動列表

`/activities` · `club` · `features/activities/ActivityListPage.tsx`

## 用途

該社所有活動申請的總覽與入口。退回件也在這裡,不另設「退回列表」頁。

## 資料來源

| 動作 | 端點 |
|---|---|
| 學期選項 | `GET /club/activities/semesters` |
| 草稿區 | `GET /club/activities?status=draft` |
| 主列表 | `GET /club/activities?semester=&status=&type=&sort=&page=`(伺服器端分頁,每頁 20) |
| 借用綁定用的已核准活動 | `GET /club/activities?status=approved&ended=false`(借用頁的下拉) |
| 詳情 | `GET /club/activities/{id}` |
| 送出 / 刪除草稿 | `POST /club/activities/{id}/submit`、`DELETE /club/activities/{id}` |
| 文件下載 | `GET /club/activities/{id}/apply-pdf` |

## 畫面

頁首:標題 + 件數 + 學期下拉(資料既有學期 ∪ 當前學期,預設最新;由 `?semester=` 進來時以網址為準)。當前學期一定在選項內,所以學期查詢失敗時畫面看不出異常 —— 下拉旁邊顯示「學期清單載入失敗 + 重試」(`components/ui/OptionsError`)。

**草稿卡片**(有草稿才出現,不分學期)— 欄位同主表,動作為「送出」「刪除」。排序:未填日期在前,再依日期新到舊。

**主表** — 狀態、名稱、類型(附大型徽章)、日期、經費、動作。狀態擺第一欄(逐列掃的是進度,不是名稱);日期欄不折行,起訖日折成兩行會讀成兩筆日期;經費欄與 `/admin/activities` 共用同一支 `components/ui/MoneyPair`,**「自籌 / 核定」兩個數字各自靠右佔一個固定寬的盒子**,兩張表因此對得齊(核定為 `null` 時顯示 `—`)。類型與狀態欄可多選篩選,名稱/類型/日期/狀態可多鍵排序,預設 `-date, -id`。動作欄:可結案時出主要鈕「結案」(有結案草稿時前面加「草稿」標記),`approved` 但未結束時顯示灰字「未開始/進行中」。

**詳情彈窗**(點任一列)— **與行政端同一支** `features/admin/ActivityReviewModal`,以 `viewer="club"` 開窗(D-34):同一份版面,社團端收掉的是審核用的東西 —— 右上角**簽核章軌**(那是審核人的簽章,社團端連姓名都拿不到)、「認可為大型活動」、繳交確認與關卡說明;`onApprove` 等簽核回呼一概不傳,整窗唯讀。

標題列「申請 / 結案」撥桿分流內容,版面細節見 [admin/review.md](../admin/review.md)(那一頁是這支彈窗的權威描述)。社團端看得到的重點:基本資料(含**經費來源**與承辦人留的**備註**)、工作分配、申請附件、經費逐項的「自籌 / 擬請 / 核定」(核定為 `null` 時顯示 `—`:承辦人還沒核定與核了 0 元對社團是兩件事)、**簽核紀錄**(關卡、時間、決議與退回原因;**簽核者姓名後端不下發給社團**,那一格因此整個不印,不是印 `—`)、結案成果全文、活動照片、成果影片與學習心得。與申請值不同的實際值(時間、地點、人數)以琥珀色 + 虛線底標示,hover 顯示預計值。逾期鎖定的單在左欄末尾加一句「已逾期並鎖定,更多疑問請洽學務處」。

右上角「⋯」下載選單:照片 zip、社團活動申請表 PDF(**走社團端那支端點**,行政端那支綁不到社團身分)。底部依狀態出「繼續編輯」/「編輯重送」/「前往結案」——`viewer="club"` 專用的兩個回呼,行政端不傳。

## 規則

- **排序、篩選、分頁全在後端**:排序白名單 `name`/`type`/`date`/`budget`/`status`(`budget` = 自籌+擬請補助逐項合計),類型與狀態漏斗以多值參數送出;同值以 id 降冪定序,換頁不會重複或漏列。**經費欄不接排序**:白名單的 `budget` 是「自籌+擬請」合計,與欄上顯示的「自籌 / 核定」不是同一件事,掛一個名實不符的指示器比沒有更糟(`/admin/activities` 同此)
- 主列表明列八種顯示狀態(不含草稿):不帶 `status` 時後端連草稿都會回,而草稿在上方獨立區
- **`status` 篩的是畫面顯示的狀態**:已核准且逾期鎖定的列顯示成「已逾期」,後端的 `approved` 因此不含它們,`locked` 是獨立的一種(推導,非 `ActivityStatus` 成員);狀態排序也照流程順序(草稿→待審核→已核准→結案審核中→已結案→已退回),不是列舉字面值
- **輸出 schema 不沿用輸入的長度限制**:`BudgetItemOut` / `ReflectionOut` 不繼承對應的 `*In`。輸出描述的是庫裡是什麼,輸入的限制是使用者能送什麼;混在一起的話舊系統遷入的列(經費明細實測最長 633 字,上限 200)會讓詳情端點 500,使用者什麼都沒做錯卻連看都看不到
- **深連結 `?semester=&open=`**(總覽的待辦與進行中申請列連過來):`semester` 決定落地的學期 —— 總覽列的活動多半不在預設(最新)學期,不帶就是落地一片空白。`open` 直接開詳情彈窗、內容由彈窗自己的查詢補齊,不等它出現在當頁列表(它可能在第 3 頁,或被目前的狀態/類型篩選擋掉)。**找不到的活動**(別社的、已刪除的)就是那支查詢的錯誤,彈窗內顯示失敗原因與重試鈕 —— 這是全站詳情彈窗的統一作法,不另跳訊息。`open` 用掉即以 `replace` 從網址移除,重新整理或返回時不會又跳出同一個彈窗
- 換頁/換條件時沿用上一份結果並淡化(`isPlaceholderData`),空狀態等抓取結束才顯示 —— 否則每次換頁都會閃一次「本學期尚無活動」

- 狀態篩選以**顯示標籤**比對,三個審核關卡在社團端都顯示「待審核」,選單不出現重複項
- `approved` 且 `close_locked` 在前端映射為顯示狀態 `locked`
- **社團活動申請表 PDF**(`GET …/activities/{id}/apply-pdf`)版面沿用舊系統的 LaTeX 版(`legacy/ClubManagementSystem/Club/GeneratePDF/activity_apply.tex`):12 欄基準格線、各列以跨欄組出欄位,結構與欄位順序不得更動。**不等結案**,草稿階段就產得出來;字型用**標楷體**(`app/assets/edukai-5.1_20251208.ttf`,教育部標準楷書),它收不到的字(中點「・」、拉丁重音字母)逐段回退 Noto Sans TC,不讓整格變豆腐。「初核 / 複核 / 決行」**依關卡取**(`APPLY_STAGES`,同一關多次核准取最後一次)—— 退回重送後承辦人會再核一次,依序排會把第二次的承辦人印在「複核」。「學校核定」未核定印 `—` 不印 0(申請表在待審階段就下載得出來,而核定 0 元是「決定不給、當場核准」的意思);頁尾的上網申請時間印的是**送件時間**(`submitted_at`,D-29;草稿退回 `created_at`),走台北時區(TIMESTAMPTZ 直接格式化會印成 UTC,早上 8 點前送的單子連日期都退一天)。「意見回饋」= 承辦人第一關認定的 `fund_source`(沒申請經費時為空)+ 固定的結報提醒,提醒一律都在
- 每列有隱形的鍵盤入口按鈕,不是只綁 `onClick`
