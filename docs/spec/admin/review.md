# 活動申請審核

`/admin/review` · `admin` · 權限鍵 `areview` / `approve_advisor` / `approve_chief` / `approve_dean` · `features/admin/ReviewPage.tsx` + `ActivityReviewModal.tsx`

## 用途

活動申請的三關簽核(或無補助的單關)。學務長本人也走這頁。

## 資料來源

| 動作 | 端點 |
|---|---|
| 待審佇列 | `GET /admin/activities?status=…`(僅登入者可簽核的狀態) |
| 最近審核 | `GET /admin/activities?status&club_id&type&sort&page`(伺服器分頁) |
| 詳情 | `GET /admin/activities/{id}` |
| 核准 / 退回 | `POST /admin/activities/{id}/approve`、`/reject` |
| 社團選項 | `GET /admin/clubs/options` |

## 畫面

**待審佇列**(上)— 只列**本關**可簽核的單(側欄徽章算同一個集合):活動名 + 大型徽章、社團 · 類型 · 送件日、活動日期、擬請補助、「審核」鈕。早的在前(ISS-99:該欄其實是活動建立時間)。整批撈回(小結果集),分頁在前端切,每頁 8。

**最近審核**(下)— 表格:社團、活動名稱、類型(附大型徽章)、活動日期、擬請補助、狀態、審核時間。狀態集合是**顯示狀態**(`features/activities/types.LISTED_STATUSES`,與社團端同一份),含推導的 `locked` —— 後端的 `approved` 篩的是畫面上的已核准、不含顯示為「已逾期」的那些,不明列 `locked` 的話逾期未結案的單會從這張表整批消失,而漏斗選項也是由這份推導的。社團/類型/狀態可多選篩選,社團/名稱/類型/日期/狀態/審核時間可多鍵排序,預設 `-reviewed_at`(無審核紀錄殿後)。伺服器端分頁,每頁 10。列表或社團選項任一失敗,表格內就改顯示失敗原因與重試鈕(不顯示「無符合篩選條件」——空結果與載不到是兩件事);已選社團而選項載不到時篩選一律 fail-closed 為空集。

**審核彈窗**(兩頁共用 `ActivityReviewModal`):
- 標題列:活動名、大型徽章、狀態 pill、右側**簽核章軌**(承 / 組 / 長 三顆章;無補助的單關不畫)
- 左:基本資料(社團、類型、日期時間、地點、參加人數、送件、**內容、工作分配**、附件連結);類型為「活動」時有「認可為大型活動(評鑑行政分 ×3 加權)」勾選框。工作分配與社團端詳情共用 `features/activities/WorkTable`(一行一列的項目 / 負責人,對齊規則同該元件)
- 右(有經費才出現):經費來源輸入 + 逐項核定表(摘要 / 自籌 / 擬請 / 核定),底部合計**落在各自欄位正下方**(併格的話核定合計會壓在擬請欄上,對不回欄名)
- **沒申請補助就沒有東西可核**:整單擬請合計 0 時,核定欄與「經費來源」輸入整個不出現(後端同一條界線:擬請合計 0 帶非零核定回 422、經費來源也只在有補助時必填);逐列同理 —— 擬請 0 的那一列直接顯示 0,不給一個 `max=0` 永遠打不動的輸入框
- 三個金額欄的寬度**由資料決定**(`types.numColWidth`:以最寬的一個數字為準):自籌/擬請各看自己的最大值,核定跟擬請同寬(核定 ≤ 擬請)再加輸入框的內距與邊框;其餘寬度全給摘要 —— 遷移進來的說明可以到數百字
- 兩塊的標題都用 `components/ui/SectionTitle`(標題 + 分隔線),與社團端詳情、結案審核同一支
- 底部:退回(必填原因的子彈窗)、核准。非本關時整個彈窗唯讀並說明原因
- 詳情查詢失敗時內容整塊換成失敗原因與重試鈕(不留列表列那半份基本資料 —— 附件與經費逐項都不在,顯示成 `—` 看起來就像沒填),底部收掉退回與核准:讀不到逐項擬請就核准等於整單核定 0 元

## 規則

- **有申請補助**(擬請合計 >0):承辦人 → 組長 → 學務長;**無補助**:承辦人單關即核准
- 經費來源、逐項核定、大型活動認可**只有第一關可編輯**,組長與學務長關唯讀核准
- 有補助時經費來源必填、每一項都要有核定金額,總額由後端加總寫入 `school_approved`
- **學務長關卡必須本人操作**:即使 `super` 也要明確持有 `approve_dean`,否則 403
- 大型活動認可:未申請也可由管理員逕行核定(勾選即 `is_large=true` + `is_large_approved=true`);已申請但不勾 → `is_large_approved=false`
- 退回原因必填,退回後狀態轉 `rejected`,社團可修改重送
- 受限關卡帳號的**視野也受限**:只看得到自己關卡相關的狀態,其他狀態的活動連詳情都回 404(避免探測)
- 每次核准/退回都寫 `approval_records` 與 `audit_logs`,並推 Discord

- **大型活動認可**:第一關是認定點(沒勾即否准),但**組長與學務長關仍改得動**(decisions.md ISS-54);後兩關省略該欄=不動,不會把已給的認可清掉
- **逐項核定不得高於該項擬請補助**(decisions.md D-03),超出回 422 `APPROVED_OVER_REQUESTED`
- **無補助案核不出金額**:擬請合計 0 時帶任何**非零**核定金額回 422(帶 0 等同不核),`school_approved` 一律寫 0 —— 單關核准的前提就是這張單不動到經費
- **相鄰關卡不得由同一人簽核**(`_require_different_actor`):同時持 `approve_advisor` + `approve_chief` 的帳號連按兩次會被擋在組長關,`super` 亦同。列鎖只擋得住同一關被重放,擋不住一路簽到底
- **退回件重送會作廢上一輪的核定**:社團不編輯直接重送也一樣,`submit` 會把逐項核定與 `school_approved` 都歸零 —— 彈窗的核定欄因此退回該項擬請金額(未核定時的預填值),而不是上一輪核過的數字
