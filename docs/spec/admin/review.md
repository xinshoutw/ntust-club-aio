# 活動申請審核

`/admin/review` · `admin` · 權限鍵 `areview` / `aact` / `approve_advisor` / `approve_chief` / `approve_dean` · `features/admin/ReviewPage.tsx` + `ActivityReviewModal.tsx`

## 用途

活動申請的三關簽核(或無補助的單關)。學務長本人也走這頁。

## 資料來源

| 動作 | 端點 |
|---|---|
| 待審佇列 | `GET /admin/activities?status=…`(僅登入者可簽核的狀態) |
| 最近審核 | `GET /admin/activities?status&club_id&type&sort&page`(伺服器分頁) |
| 詳情 | `GET /admin/activities/{id}` |
| 核准 / 退回 | `POST /admin/activities/{id}/approve`、`/reject` |
| 社團選項 | `GET /admin/clubs/options` |

## 畫面

**待審佇列**(上)— 只列**本關**可簽核的單:活動名 + 大型徽章、社團 · 類型 · 送件日、活動日期、擬請補助、「審核」鈕。送件早的在前。

**最近審核**(下)— 表格:社團、活動名稱、類型(附大型徽章)、活動日期、擬請補助、狀態、審核時間。社團/類型/狀態可多選篩選,社團/名稱/類型/日期/狀態/審核時間可多鍵排序,預設 `-reviewed_at`(無審核紀錄殿後)。伺服器端分頁,每頁 20。列表或社團選項任一失敗,表格內就改顯示失敗原因與重試鈕(不顯示「無符合篩選條件」——空結果與載不到是兩件事);已選社團而選項載不到時篩選一律 fail-closed 為空集。

**審核彈窗**(兩頁共用 `ActivityReviewModal`):
- 標題列:活動名、大型徽章、狀態 pill、右側**簽核章軌**(承 / 組 / 長 三顆章;無補助的單關不畫)
- 左:基本資料(社團、類型、日期時間、地點、參加人數、送件、附件連結);類型為「活動」時有「認可為大型活動(評鑑行政分 ×3 加權)」勾選框
- 右(有經費才出現):經費來源輸入 + 逐項核定表(摘要 / 自籌 / 擬請 / 核定),底部擬請合計與核定合計
- 底部:退回(必填原因的子彈窗)、核准。非本關時整個彈窗唯讀並說明原因

## 規則

- **有申請補助**(擬請合計 >0):承辦人 → 組長 → 學務長;**無補助**:承辦人單關即核准
- 經費來源、逐項核定、大型活動認可**只有第一關可編輯**,組長與學務長關唯讀核准
- 有補助時經費來源必填、每一項都要有核定金額,總額由後端加總寫入 `school_approved`
- **學務長關卡必須本人操作**:即使 `super` 也要明確持有 `approve_dean`,否則 403
- 大型活動認可:未申請也可由管理員逕行核定(勾選即 `is_large=true` + `is_large_approved=true`);已申請但不勾 → `is_large_approved=false`
- 退回原因必填,退回後狀態轉 `rejected`,社團可修改重送
- 受限關卡帳號的**視野也受限**:只看得到自己關卡相關的狀態,其他狀態的活動連詳情都回 404(避免探測)
- 每次核准/退回都寫 `approval_records` 與 `audit_logs`,並推 Discord

## 未完成 / 問題

- **無補助案可由承辦人單關核定任意金額,完全不經組長與學務長**:套用 `body.budget` 與加總寫入 `school_approved` 都是無條件執行,`requested_total > 0` 只 gate 驗證;而擬請 0 元時狀態直接轉 `approved`
- **缺「相鄰關卡簽核人須不同」的約束**:列鎖 + 重讀狀態已擋住同一關被重放,但 `_require_stage_key` 對 advisor/chief 一律放行,連續兩次 POST 會走完 advisor→chief。組長關卡**不是被跳過**(照樣寫了 `stage="chief"` 的紀錄),而是同一人連簽兩關。不限 super,任何同時持兩個簽核鍵的帳號都一樣
- 核定金額不受「擬請補助」上限約束 —— 前端 `InputNumber max` 只擋鍵入,API 完全不擋
- 退回件若社團直接重送(不編輯),舊的逐項核定金額會沿用(只有走 PUT 才會被 `replace_budget_items` 歸零);更糟的是彈窗會把舊核定值**預填回輸入框**,承辦人看到一份「已填好」的核定表,順手按核准就原封不動再送一次
- 社團編輯退回件後 `school_approved` 未同步清除,仍是上一輪的核定總額
- 大型活動認可只能在第一關寫入;承辦人忘了勾就永久固化為「否准」,後續關卡與退回重送都無法補正
- 沒有批次核准,也沒有「退回=退到底」以外的流程選項;衝突連鎖自動駁回未做
