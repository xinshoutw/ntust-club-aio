# 社團詳細

`/clubs/:clubId`(免登入) · `features/public/ClubDetailPage.tsx`

## 用途

單一社團的公開頁:介紹、聯絡方式、入社資訊、已核准的活動列表(點開看內容與結案照片)。這是社團對外可分享的那個網址。

## 資料來源

| 區塊 | 端點 |
|---|---|
| 社團資料 | `GET /public/clubs/{id}` |
| 活動列表 | `GET /public/clubs/{id}/activities`(彈窗要的活動內容與照片 id 同在一列上) |
| 圖片 | `GET /public/files/{id}` |
| 活動照片 | `GET /public/files/activity-photos/{id}` |

## 畫面

- 橫幅:3:1 的圖,**上面不壓任何文字**
- 標題卡:**方形頭像固定 148px**(560px 以下退回 72px,免得長社名把頭像撐爆),右側依序為
  社團名稱、英文名稱、一句話介紹、性質與標籤,**招生狀態靠這張卡的右上角**。
  不用 `align-self: stretch` + `aspect-ratio: 1` —— 那樣頭像會在圖載好的瞬間從 88px 跳到
  148px,底下整批位移 38px(理由留在 `publicClubs.css` 的註解裡,別改回去)
- 兩欄:左為介紹卡(社團簡介全文、社辦位置、例行活動時間),右為聯絡卡(Email、Instagram、
  社團網頁)與入社卡(入社方式與社費、報名連結)。**左欄那張卡的高度吃滿右欄兩張卡疊起來的高**
  (grid 預設 stretch + `flex: 1`);760px 以下改單欄
- 活動紀錄:**全寬**,放在兩欄下面。欄位為日期、時間、活動名稱、地點,**日期與時間不換行**。
  端點另帶 `is_large` 與 `type`,畫面不顯示;**`start_time`/`end_time` 會是 null**
  (只填日期不填時間的活動),照全站慣例畫成 `—`,不可以 `?? '00:00'`。
  **不是 `tb fixed` 表格而是四欄 grid**(`.act-list`,`publicClubs.css`):固定欄寬得先猜
  地點要多寬,而猜窄了長地點就折行 —— 「趨勢科技 Trend Micro 股份有限公司」在 1440px 上
  照樣折成兩行,同一列的活動名稱那一欄卻空著三百多 px。改成日期、時間與地點各取自己的
  `max-content`,活動名稱吃掉剩下的全部(`1fr`)。**名稱欄有 `12em` 下限**當地點欄的煞車:
  庫裡最長的地點有 42 個字(518px),沒有下限的話它在 768px 上會把名稱壓到見底
- **一則紀錄一個 `listitem`**:`.act-list` 是 `role="list"`、每一列 `role="listitem"`,
  四個欄位各自帶 `.sr-only` 欄位名(`日期` / `時間` / `活動名稱` / `地點`),表頭整列
  `aria-hidden` —— 表格收掉之後沒有東西把表頭與格子關聯起來,而手機的字卡連表頭都沒有。
  **列一定要是真的盒子**:原本用 `display: contents` 讓四格直接參與父格線,但那種元素在
  舊版引擎會連同 role 一起被拿出無障礙樹,一則紀錄就沒有邊界、數不出有幾筆。
  現在改 `grid-template-columns: subgrid`,欄寬照樣由整份清單一起決定
- **活動彈窗**(D-42):點一列開 AntD `Modal`,標題是活動名稱,內容是日期、時間、地點、
  活動內容(申請時填的,沒填是 `—`),**有結案照片才**多一段「活動照片」縮圖牆(4:3 置中裁切,
  點開是 AntD `Image.PreviewGroup` 的預覽,整組左右切換)。資料全在清單那一列上,不另打詳情端點,
  所以彈窗沒有載入中的狀態;個別照片載不出來(照片通道回 404)就收掉那一張,全收掉就整段不出現,
  不留破圖;預覽開著時先不收(組內少一張,預覽會停在「5 / 4」的空白),預覽的淡出跑完才收。**整列 onClick 只服務滑鼠,鍵盤入口是名稱那顆
  `.row-open-btn`**(design-guide §6)—— 列本身不能掛 `role="button"`,那會蓋掉 `listitem`。
  hover 用 `.click-tint`,桌機另以 box-shadow 左右各多塗 12px:列沒有水平內距(欄寬由 subgrid
  決定,加內距會連表頭一起位移),直接塗底色字會貼著色塊邊緣
- **767px 以下同一份標記換成一列一張字卡**(design-guide §4.3 的「表格轉卡片列」):
  名稱獨佔一行、日期與時間並排、地點自己一行並帶 `EnvironmentOutlined`(字卡上沒有欄位
  標題,地點要自己說明自己;桌機的表頭還在,圖示收掉)。原本是 `min-width: 600px` 的表格
  配水平捲軸 —— 手機上只看得到日期與時間兩欄,活動名稱與地點要左右拉才看得到

## 規則

- 社團不存在、`is_active=false` 或 `public_visible=false` 一律 **404**,不是「已停社」頁 —— 對外沒有必要交代某個社團曾經存在
- 公開的活動是**通過審核以後的**:`approved`、`closing_pending_advisor`、`closed` 三個狀態。審核中、退回與草稿一律不回(舊系統的公開月曆沒過濾狀態,把審核中的草稿全放出去了,這是同一個坑)
- 活動**回 `content`(活動內容)、不回任何金額**(D-42):活動內容是申請時寫的那段介紹(上限 150 字),
  點開一場活動想知道的就是它;補助、經費來源與承辦備註是學務處與社團之間的事
- **結案照片只公開結案通過(`closed`)的活動**:結案準備中(`approved`)的照片是社團還在刪換的草稿,
  送審中的還沒有承辦看過。清單的 `photo_file_ids` 與照片通道共用同一份判定
  (`api/v1/public._public_photos`:活動 `closed`、社團公開、未歸檔、`slot=report_photo`、
  來源不超過預覽上限)—— 各寫一份就會出現「清單列得出來、點下去 404」
- **照片通道一律送轉過的 JPEG,不送原檔**(`files.preview_of`,長邊 1600,與站內 `<img>` 看 HEIC
  的預覽共用快取):手機原圖動輒數 MB(開發庫平均 1.9 MB,轉完平均 241 KB),而且 EXIF 帶拍攝座標
  (抽樣 300 張有 20 張有 GPS)—— 重新編碼的 JPEG 不帶這些拍攝資訊。轉不出來(解不開、超過
  像素上限、磁碟到告警水位不再建新快取)**一律 404,不退回原檔**。EXIF 與 XMP 不寫出去、JPEG 的
  COM 註解清空(開發庫 72 張帶著 Discord 寫進去的 JSON);ICC 色彩描述檔保留(RGB 來源才留,
  P3 的照片少了它會整張變淡;超過 64 KB 的丟掉 —— 那不是顯示用的 profile,是夾帶的資料)。這條通道匿名打得到,所以:**轉不出來的來源在行程內記住**
  (`files._PREVIEW_FAILED`,10 分鐘後才重試 —— 原檔暫時讀不到這類會好的錯誤不必等重啟),
  同一張壞圖不會被反覆拿來佔住只有兩條的轉檔池,同一張的並發請求也只轉一次;轉檔池裡已經有 16 張
  (`public.PUBLIC_PREVIEW_BACKLOG`)就不再排新的一張、先回 404(不記失敗)—— 斷線不會取消 handler,
  列舉照片 id 一張張打就能排出幾分鐘吃滿 CPU 的佇列;形象圖轉 WebP 另走一條 thread,不排在它後面;
  **排隊轉檔前先把 DB 連線還回池子**。來源超過 20 MB 的不列
  (開發庫 4,017 張裡有 7 張)。路徑掛在 `/public/files/` 底下是為了吃 nginx 給圖片的
  限流桶(`public_files`);快取與形象圖同一個取捨(`private, max-age=3600`)
- 活動列表依開始日新到舊,**只列最近 10 次**;帶 `semester`(`\d{1,3}-[12]`)可指定學期,不帶即全部。公開頁回答的是「這個社團在辦什麼」,不是完整流水帳。
  **學期不是欄位**而是由開始日推導(`core/semesters`),所以篩的是日期區間;沒有開始日的
  (只有草稿會這樣)一律不回
- 社團不公開時**連活動都查不到**:`/public/clubs/{id}/activities` 先驗社團再查活動,
  否則下架的社團仍可由活動端點反推存在
- 對外聯絡信箱是 `public_email`,**不是 `contact_emails`** —— 那三組是公告通知的收件人,屬內部設定
- Instagram **只顯示帳號**(`@ntust_dance`),不顯示 `instagram.com/` 前綴;庫裡存的也是純 ID
- 指導老師(`advisor_*`)、幹部與社員名單、停權狀態、Discord webhook 一律不出現在任何公開端點
- 每一列帶 `id`:前端不顯示單號(design-guide §6),但列表要一個穩定的 key —— 同日同名的
  兩場活動拿「日期+名稱」當 key 會互撞
- 橫幅與字卡用同一個比例(3:1),兩邊都不裁切,見 [club-directory.md](club-directory.md)
